# Introduction à la programmation orientée objet

La **programmation orientée objet** (POO) est un paradigme de programmation qui
organise le code autour d'**objets** plutôt que de fonctions et de données
séparées. Un objet regroupe à la fois des données (ses **attributs**) et les
fonctions qui agissent sur ces données (ses **méthodes**). Cette approche rend
le code plus facile à réutiliser, à maintenir et à faire évoluer.

Le concept remonte aux [années 1960](https://fr.wikipedia.org/wiki/Programmation_orient%C3%A9e_objet)
avec le langage Simula, mais c'est C++, Java et Python qui l'ont popularisé.

## Classe vs objet

Il est essentiel de bien distinguer une **classe** d'un **objet** (ou instance).

- Une **classe** est un **modèle** (un plan de construction). Elle décrit la
  structure et les comportements que ses objets auront.
- Un **objet** est une **réalisation concrète** de cette classe. On peut créer
  autant d'objets que l'on veut à partir d'un même modèle, chacun ayant ses
  propres données.

**Analogie :** une classe est comme le plan d'architecte d'une maison. Un objet
est une maison construite à partir de ce plan. On peut bâtir plusieurs maisons
identiques dans leur structure, mais chacune a sa propre adresse, ses propres
occupants, sa propre couleur de porte.

## Le fil rouge : `CompteBancaire`

Pour illustrer les 4 piliers tout au long de ces notes, nous allons construire
progressivement une hiérarchie de classes bancaires.

## Définir une classe

En Python, on définit une classe avec le mot-clé `class`. Par convention, le
nom d'une classe commence par une **majuscule**. Voici un exemple de classe
simple représentant un compte bancaire :
```python
class CompteBancaire:
    def __init__(self, titulaire, solde_initial=0.0):
        self.titulaire = titulaire
        self.solde = solde_initial

    def deposer(self, montant):
        self.solde += montant

    def retirer(self, montant):
        if montant > self.solde:
            print("Fonds insuffisants.")
        else:
            self.solde -= montant

    def afficher_solde(self):
        print(f"{self.titulaire} — Solde : {self.solde:.2f} $")
```

Pour créer des objets à partir de cette classe, il suffit de l'appeler comme
une fonction, en passant les arguments nécessaires au constructeur `__init__` :

```python
compte_alice = CompteBancaire("Alice", 1200.0)
compte_bob   = CompteBancaire("Bob")           # solde_initial = 0.0 par défaut

compte_alice.deposer(500)
compte_alice.afficher_solde()  # Alice — Solde : 1700.00 $
compte_bob.retirer(100)        # Fonds insuffisants.
```

### Attributs et méthodes

- Les **attributs** sont les données propres à l'objet. Ils sont créés dans
  `__init__` avec `self.nom = valeur` et accessibles avec la notation pointée
  `objet.attribut`.
- Les **méthodes** sont les fonctions définies dans la classe. Elles prennent
  toujours `self` comme premier paramètre.

```python
compte = CompteBancaire("Charlie", 500)

print(compte.titulaire)   # "Charlie"   — accès à un attribut
print(compte.solde)       # 500         — accès à un attribut
compte.deposer(200)        #            — appel de méthode
```

### Le constructeur `__init__` et `self`

Le **constructeur** est la méthode `__init__`. Python l'appelle automatiquement
à chaque création d'objet. Son rôle est d'**initialiser les attributs** de
l'objet à sa naissance.

Le premier paramètre est toujours `self`. Il représente **l'objet lui-même** en
cours de construction — une référence qui permet à la méthode d'accéder aux
données propres à cet objet et de les distinguer de celles d'un autre objet de
la même classe. Vous n'avez jamais à fournir `self` vous-même : Python le passe
automatiquement.

```python
compte_a = CompteBancaire("Alice")
compte_b = CompteBancaire("Bob")

# compte_a.titulaire et compte_b.titulaire sont deux variables distinctes
# même si elles ont été créées par le même __init__
```

En réalité, lorsque vous écrivez `compte_alice.deposer(500)`, Python traduit
cela en un appel à la méthode de la **classe** en lui passant l'objet
explicitement comme premier argument. Ces deux formes sont strictement
équivalentes :

```python
compte_alice = CompteBancaire("Alice", 1200.0)
compte_bob   = CompteBancaire("Bob")

# Forme habituelle — Python passe self automatiquement
compte_alice.deposer(500)
compte_alice.afficher_solde()  # Alice — Solde : 1700.00 $
compte_bob.retirer(100)        # Fonds insuffisants.

# Forme explicite — équivalente, mais plus verbeuse
CompteBancaire.deposer(compte_alice, 500)
CompteBancaire.afficher_solde(compte_alice)  # Alice — Solde : 1700.00 $
CompteBancaire.retirer(compte_bob, 100)      # Fonds insuffisants.
```

Appeler la méthode depuis l'objet (`compte_alice.deposer(500)`) est donc un
raccourci syntaxique : Python identifie automatiquement la classe de l'objet et
lui transmet l'instance comme `self`.

:::info Pas de surcharge de constructeur
Contrairement à Java ou C++, Python ne permet pas de définir plusieurs
`__init__`. On compense avec des **valeurs par défaut** ou des
**méthodes de classe** (constructeurs alternatifs), que nous verrons dans la
page [Encapsulation](./encapsulation).
:::


## Constructeurs et destructeurs

### `__init__` — constructeur

Vu ci-dessus. Python l'appelle à la création de chaque instance.

### `__del__` — destructeur

La méthode `__del__` est appelée lorsque l'objet est sur le point d'être détruit
par le ramasse-miettes de Python (quand plus aucune variable ne le référence).
Elle sert généralement à libérer des ressources (fermer un fichier, une
connexion réseau).

```python
class CompteBancaire:
    def __init__(self, titulaire):
        self.titulaire = titulaire

    def __del__(self):
        print(f"Compte de {self.titulaire} fermé.")

c = CompteBancaire("Alice")
del c   # Compte de Alice fermé.
```

:::caution Utilisation limitée
Le destructeur n'est **pas garanti** d'être appelé dans tous les cas
(références circulaires, arrêt brutal du programme). Pour la gestion fiable de
ressources, préférez les **gestionnaires de contexte** (`with`).
:::
